# Yōkai iOS

Native iOS port under active development. The intended baseline is the original Yōkai feature set and workflows, with the Tachimanga Premium features requested by the user and WebDAV inside Backup & Restore. The user explicitly excluded external tracker services (AniList, Bangumi, MyAnimeList, etc.) on October 7; local reading progress remains required. Android backup import/export is part of that baseline. Feature parity is not yet complete; a successful build is not a claim of parity.

## Current implementation

- Original Android extension JARs run inside the iPhone process using OpenJDK Mobile's Zero interpreter, without JIT or an Android server. APK imports use the bundled Dex2jar converter. Each extension has an isolated class loader.
- Eight bundled sources: vomic, 巴卡漫画, 香香腐宅, 漫蛙, 哔咔漫画, 花咔漫画, 拷贝漫画, 热辣漫画. Five requested repository URLs are retained exactly in `Yokai/ExtensionRepositories.json`; repository catalogs and extension updates are supported. Protobuf indexes are read directly, with legacy JSON fallback. The local 花咔 plugin is included in this repository as `Runtime/bundled/Huakacomic.kt` and the complete `Runtime/bundled/huakacomic.jar`; `Runtime/prepare.py` bundles that JAR into the app. It has no extension-index update owner yet. The other seven bundled packages are associated with their update repositories. Daily automatic checks and automatic installation are separate opt-in switches under Browse → Extensions; both default to off. A due check runs during launch/foreground maintenance or an iOS-granted refresh opportunity. Only a higher versionCode from the installed package's associated repository is offered; downloads are inspected and loaded before replacement, and a failed import restores the previous installed set. This is not guaranteed daily background execution under LiveContainer.
- Popular/latest/search, complete plugin filter forms, saved searches, global search, source pin/hide/language controls, source migration, manga details, chapter lists, plugin settings, WebView with plugin User-Agent and headers, and Cookie transfer back to the extension before refreshing. Credentials/preferences and extension Cookies are stored through Keychain.
- Shelf, Recents (updates/history), Browse (sources/extensions), and More menu with downloads, Backup & Restore, and settings. Shelf selection pushes manga details and its chapter list; selecting a chapter or the separate start/continue button opens the reader, matching Android's LibraryController/MangaDetailsController. The manga header follows the original cover/title/author/status/source/action/summary order. Chapter rows show dates, progress, bookmarks, and download state, with source/number/date sorting, filters, swipe actions, and selection.
- Library categories with add/rename/reorder/delete and default category assignment; grid/cover-only/list display, grouping, sorting, filters, badges, multiple selection, bulk categories/read/download/remove actions.
- Shelf cover dimensions are constrained to their grid cells. Online books use cached source covers rather than chapter-page thumbnails; custom covers are stored separately. Successful manga details/chapter lists are cached, and failed requests preserve cached chapters. Reading/downloading does not automatically favorite a manga; removing it from the shelf preserves its cached files and reading history.
- CBZ/ZIP/PDF/image import; LTR/RTL, vertical pager, webtoon and continuous vertical reading; per-book reading defaults, orientation, automatic/single/double/split page layouts, zoom, bookmarks, cropping, autoscroll, grayscale/inversion, brightness, page numbering and screen-awake settings. Wide spreads remain alone in double layout; split layout follows reading direction and can exchange halves. Continuous reading can stack a spread's halves vertically. Paged images support fit/fill/width/height/original/smart/stretch sizing and zoom starting position; continuous reading supports pinch/double-tap zoom and optional zoom-out. Reader chapter navigation uses the cached chapter order, skip rules and optional download-ahead. Tap navigation preserves Yōkai's default/L/Kindlish/Edge/Left-and-Right/Disabled layouts and horizontal/vertical inversions. Continuous taps scroll three quarters of the viewport, as in Android. Color overlays preserve Android's ARGB values and default/multiply/screen/overlay/lighten/darken modes. Negative brightness adds dimming at minimum screen brightness; zero uses the prior system brightness. Long-press menus save/share original images and set covers. Saving to Photos asks for add-only access through iOS.
- Animated WebP, GIF and APNG pages play with their frame timing and loop counts in continuous and paged reading, including loose downloads and CBZ entries. Frames decode on demand off the main actor; background and offscreen playback pauses. Split/stacked spreads and a fixed border crop are applied to each frame.
- Manga titles, authors and artists open global search on tap and offer field-specific copy actions on long press, including local/cached details; descriptions and genres support text selection. Shelf menus can copy titles. Library source filters support multiple inclusions and exclusions, including local books and missing plugins. History renders in batches of 50 while search covers the full history.
- Reader toolbar buttons can be added, removed and reordered. Controls use native Liquid Glass on supported systems and adapt to narrow or wide windows. Continuous and paged custom tap zones store separate layouts/actions, with legacy settings and native backup restore preserved. In continuous reading, holding the screen edge scrolls; vertical dragging adjusts speed and release stops. Autoscroll uses display-synchronized elapsed time and requests the display's supported maximum refresh rate; iOS still chooses the actual rate.
- Persistent download queue with pause/retry/cancel/reorder/checkpoints, Wi-Fi restriction, new chapter downloads with category inclusion/exclusion, CBZ storage and configurable removal after reading/marking/remote chapter removal. Like Android, at most five sources download concurrently, with one chapter per source and two images per chapter. Reading opens only after a contiguous prefix of images is ready. Chapter page lists and completed images survive interruption; an actual source failure clears stale URLs for the next retry. Committed CBZ files can complete finalization after interruption without redownloading. On iOS 26+, explicitly tapping Download/Resume submits a `BGContinuedProcessingTask` with system progress and cancellation, retaining original plugin image interception/decryption. Older iOS and rejected requests use the ordinary short background window. Automatic library downloads/prefetch do not submit this user-initiated task. A system-cancelled batch stays paused until explicitly resumed; ordinary background-time expiry resumes on foreground. System scheduling and LiveContainer compatibility still require real-device validation.
- WebDAV synchronizes shelf metadata, chapter progress, bookmarks, and deletion records. It uses strong ETags and conditional writes, and asks about conflicting reading positions. Image files and credentials stay on-device. JSON backup/restore includes iOS settings, cached manga details/chapter order, and optional source preferences. Android `.tachibk`/`.proto.gz` import and `.tachibk` export preserve chapter progress/bookmarks/history, metadata, categories, memo fields and uninterpreted per-manga tracker fields. Original and custom title/author/artist/description/genre/status remain separate in exports. Android restore follows the original rules: retain completed chapters and bookmarks, keep a nonzero local page when the backup page is zero, merge history by its latest date, and match categories by name. Supported Android app preferences, including original tap presets/inversions, scaling, page layouts and filters, are mapped to the iOS equivalents; other preferences are retained on-device for export, as are category flags and source names. Source preferences are restored through the existing Keychain bridge and source factories reload. Android export currently includes online manga; local file metadata is covered by native JSON backups. Source preferences may contain login details, as in the original Android format. iOS page bookmarks and per-book layout options have no direct equivalent in the original Android backup schema.

- Tachimanga `.tmb` import reads the nested ZIP and SQLite database locally, restoring favorite titles, non-favorite reading history, categories, chapter lists/order, read flags, page counts/positions, bookmarks, per-title reading mode and source preference plists. Mixed seconds/milliseconds timestamps and 64-bit source IDs are preserved. Restoring merges with the existing library and never removes an existing favorite merely because it appears only in the backup history. It retains the installed extension runtime; archived JARs and unsupported Tachimanga appearance/app settings are not restored.

- Scheduled library updates with category and completed/unstarted exclusions, Wi-Fi/charging conditions, foreground due checks and native iOS background refresh requests. Scheduled Android-format backups support a selected directory and retention count. iOS controls background execution timing.
- The runtime Application delegates to its initialized Context, allowing original source cache access. Zstd source responses use the pure-Java Aircompressor decoder behind the original Okio Zstd API; this avoids loading Android/native JNI binaries.

## Build and install

The optional native [ReadingHub host](ReadingHub/README.md) composes this implementation with qiye-reader, preserving both standalone build targets. Its direct installation reuses the existing Qiye bundle identity and keeps the two libraries in separate storage namespaces.

`./build-ipa.sh` prepares pinned runtime dependencies and produces a development-signed `build/Yokai.ipa`, without needing a connected phone. `./build-ipa.sh --upload-livecontainer` copies it to the installed LiveContainer's Documents directory; import it in LiveContainer and replace `com.wyih.yokai.app` to retain its data. `--install-direct` is for devices with a free independent signing slot. `YOKAI_TEAM`, `YOKAI_DEVICE`, `YOKAI_CONTAINER`, and `YOKAI_DESTINATION` override local defaults. The default build destination is generic iOS. Personal Team provisioning requires periodic renewal.

Runtime preparation lives in `Runtime/prepare.py` and `Runtime/dependencies.json`. A JDK 23 BasicImageWriter creates a format-1.0 jimage compatible with the mobile runtime; the app bundles no exploded `.class` files, which prevents LiveContainer's signer from mistaking Java bytecode for Mach-O fat binaries. The image includes `jdk.zipfs`, required by Dex2jar when importing or updating APK extensions; runtime preparation rebuilds cached images when their builder changes. `python3 Tests/check_extension_artifacts.py` checks the image and converts/loads APK and JAR fixtures with the iOS module set. OpenJDK's required JNI symbols are retained using `-all_load`. Runtime and dependency notices are bundled under `Notices`.

`swift test` checks synchronization merges and WebDAV protocol behavior. Xcode builds target the physical iPhone. The OpenJDK simulator runtime has an upstream code-cache initialization issue, so plugin execution must be tested on a real device.
